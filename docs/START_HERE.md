## 1. Purpose

This is the only development-document entrypoint retained in the working tree.
Earlier plans, status snapshots, audit narratives and batch documents are removed
from the active tree. Git history remains the recovery source, but historical
documents have no authority over current implementation, qualification or release.

G1 turns the existing Owner-Open source closure into a modular engineering
program suitable for dozens of engineers. It preserves the proven correctness
principles while adding explicit module ownership, concurrency partitions,
resource budgets, global mechanical coordination, performance evidence, rollout
and compatibility rules.

## 3. Truth rules

The checked-in prose defines policy and design. It does not prove the current
Git head passed. Exact source, tree, workflow, artifact and review identities are
generated by CI and referenced by machine state.

The source of truth is split by concern:

- `machine/current-baseline.v1.json` — trunk, latest source-CI head, source parent and documentation candidate;
- `machine/program-state.v1.json` — active program, phases and capabilities;
- `machine/module-catalog.v1.json` — module boundaries, dependencies, owners, state and SLO contracts;
- `machine/requirement-graph.v1.json` — requirement-to-module-to-gap-to-evidence graph;
- `machine/gap-register.v2.json` — every open or closed gap and its exit level;
- `machine/global-objective.v1.json` — hard constraints, soft objectives and workloads;
- `machine/evidence-index.v1.json` — retained evidence identities and claim ceilings;
- `machine/doc-set.v1.json` — complete active document set and forbidden legacy paths.

Everything under `generated/` is produced from these files and must never be
edited by hand.

## 4. Non-negotiable invariants

- Codex/provider is the only semantic principal.
- The global control plane is mechanical: budgets, placement, leases, fencing,
  health, rollout and reconciliation only.
- Valid shell or ADB semantics are never rewritten by broker, transport,
  runtime, scheduler or store.
- Identity conflicts are rejected before effect.
- An uncertain effect is never automatically redispatched.
- Client disconnect, delivery backpressure and timeout are not proof of
  cancellation.
- Required durable acceptance happens before an effect attempt.
- All frames, queues, stores, processes, descriptors and resource budgets are finite.
- Every state partition has one authoritative writer epoch and fencing token.
- Source, installed target, Android image, physical device, destructive fault
  and public release claims remain separate evidence levels.
