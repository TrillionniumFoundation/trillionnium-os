Trillionnium OS arm64 Mobian sudo-binfmt configured rootfs smoke
==================================================================

Status: arm64-mobian-rootfs-sudo-binfmt-configured-smoke-pass

Development position:
- arm64-mobian-configured-rootfs-built-local-sudo-binfmt

What this gate proves:
- Passwordless sudo is available for the operator-invoked rootfs build.
- A temporary qemu-user binfmt_misc entry is registered from the private
  target-local qemu-aarch64-static binary, and arch-test arm64 reports ok.
- mmdebstrap --mode=sudo --variant=apt --format=directory builds a configured
  arm64 Debian bookworm/Mobian-compatible rootfs with the four arm64
  Trillionnium packages plus Phosh/Phoc/Squeekboard payloads.
- The rootfs has a populated dpkg status database and installed package
  records for:
  - trillionnium-command-center
  - trillionnium-command-center-ui
  - trillionnium-os-daemon
  - trillionnium-shell
- The configured rootfs also has installed phosh, phoc, and squeekboard.
- sudo chroot <rootfs> /usr/bin/trillionniumd --print-manifest executes
  through the temporary qemu-user binfmt entry and emits the expected
  trillionnium.tool.v1 system.status manifest.
- File-mirror placeholder paths from local .deb injection are removed after
  mmdebstrap: 6 placeholder refs before cleanup, 0 after cleanup.
- The temporary binfmt entry is unregistered before JSON evidence is emitted.

- This gate does use sudo, network download through mmdebstrap, temporary
  binfmt_misc registration, qemu-user execution, and rootfs package
  configuration inside the target rootfs.
- It does not run host apt install, host dpkg install, rustup, cargo build, host
  package install, persistent binfmt registration, image build, ADB, Fastboot,
  flash, wipe, repartition, sideload, reboot, bootloader relock, remote push,
  model invocation, or tool invocation.
- This is still not proof that Trillionnium OS is installed on a phone. The next
