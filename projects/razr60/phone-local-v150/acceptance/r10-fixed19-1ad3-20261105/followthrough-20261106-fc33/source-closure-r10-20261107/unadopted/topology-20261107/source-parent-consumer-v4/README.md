source-parent consumers execute with the v3 derived reader, validate its new

inventory function. All changes live in a separately identified, unadopted
module. Frozen runtime files, receipts, v1/v2/v3 packages and admission rules
remain untouched.

context, raw-byte/descriptor checks and source-parent classification therefore
run before the new consumer. The preserved current inventory function's former
quadratic root-pair predicate is replaced by the same canonical parts-prefix
function already tested in v1/v3. Its property-reader helper pin changes to the
actual new function, and the original restricted builtins remain unchanged.

The consumer checks the exact new envelope keys, schema, method, full execution
provenance and claim ceiling before it uses a result. It distinguishes an object,
the original three-object closure tuple, and the original `None` full-tail return.
It rejects a claimed old execution, adoption, runtime admission, current native
credit, budget verification, or a changed actual producer identity.

The envelope is an in-process return from the separately pinned fresh producer.
It is not a signature or an authenticator for arbitrary external JSON receipts.
The public consumer methods take original bytes and descriptors; they do not
accept an externally supplied result in place of executing the producer.

The initial bound producer provenance is immutable source-construction identity.
Every selection constructs a fresh producer, rechecks its complete identity, and
runs historical validation again. No validation result or observation is cached.
The actual full replay repeats closure and confirms the same original callback
reads occur again. Existing fresh nested-module compositions are inherited and
disclosed; preexisting external modules are not reassigned. The constructor
restores import path, bytecode policy and the prior `component_common` module.

The public interface contains six reader/consumer entries. Runtime, publication,
current-observation and whole-chain I/O entries are removed from its selected
module. This API is not the new stage/production selector. Its explicit supplied
original callback is an I/O boundary; the constructor does not attest that
callback's implementation or complete production I/O metering.
