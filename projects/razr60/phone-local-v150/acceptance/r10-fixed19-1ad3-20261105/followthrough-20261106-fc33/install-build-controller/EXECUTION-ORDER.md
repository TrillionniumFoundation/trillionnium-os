## Original controller records and exact maps

Each complete controller carrier supplied for an actor or P4 file observer is JSON with `request`, `start`, `status`, and `read` (or `reads` for a paginated observer). The `start`, `status` and `read(s)` values are the original MCP envelopes, preserving their inner `content[].text` strings. Do not parse/re-encode that inner JSON in JavaScript: nanosecond/full9 integers exceed the safe integer range. Keep complete text plus raw hex, contiguous offsets, final EOF, durable terminal and original failure fields. An actor emits a small CLI summary; its actual phone streams come from its independently retained `result.json`.

The installed-original-map input is one JSON list of exact `{namespace, original, retained}` rows. `namespace` is `phone_gnu`; each original and retained descriptor has exactly `path`, `bytes`, `sha256`, `metadata`, where metadata is the actual nine-element integer list. It must be generated from a real read-only phone capture. This package does not invent that capture or derive phone metadata from BUILD files. Needed fixed paths are those in the already published exact8 reader: four module files, READY source (also retained from the actual source guard), four `<role>.identity`, three `owner-<role>.bind.json` and their three `<role>.spawn-pid`. Historical empty-log identities already embedded in the source-bound child-bind records are not replaced with current growing log contents.

The constructors automatically add actual metadata for existing host dependencies and deduplicate an original only after both retained aliases have been read and verified. Proposed output inode values are never inserted. Phase ingestion first publishes raw files, then reads their real full9 to construct the carrier. Original phase/process content is never rewritten to make a failed result succeed.
