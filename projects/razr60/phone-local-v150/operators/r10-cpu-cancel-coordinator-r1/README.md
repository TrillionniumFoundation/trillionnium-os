# NEG08/NEG09 one-case coordinator, unbound source candidate r1

This package supplies the missing top-level connection between the existing
sender, the actual Cancel Actor, both original collectors and the CPU closer.
The implementation is complete enough for source review and local regression.
`FINAL_AUTHORITY` remains `None`. It has not been installed, sent to either host,
or used to run a phone case. The current policy/frontier must be independently
resolved before a reviewed source revision can bind execution authority.

The regression result is **25/25 local groups passed**. It is implementation
evidence and gives **zero acceptance case credit**. No synthetic READY, old
source manifest, offline policy candidate or historical scope is promoted to
current authority.

## Execution sequence

The entry accepts an existing explicit nonce and exact request/template inputs.
It never generates a nonce, registers a request, substitutes a native scope, or
creates a replacement identity after failure.

1. Before reading a private case plan or creating an output, require a frozen
   source literal containing actual source descriptors and final dependencies.
   Load the actual CPU assembler and apply its full source-chain checks. Verify
   the root closer's sibling `PURE_MODULES` pins before any case dispatch.
2. Validate the exact existing plan, the prior terminal task, preserved Chinese /
   emoji / multiline draft, and the request's registered v150.3 template. Build
   the Actor plan through the unchanged actual `cancel_phase.validate_plan`.
   The current Actor's stricter 15–180 second wait range remains in effect;
   the closer's broader 1–300 range does not widen it.
3. Require the fixed local closure input/output parents and absent case leaves.
   Prepare six fixed private host family directories when absent, then create
   the exact P4 case input and control namespaces. Existing leaves or once
   markers reject the attempt. There is no overwrite, cleanup or new suffix.
4. Execute the Actor's preview on P4. Run a separately bounded read-only phone
   preflight using the actual pinned active/runtime/observer/decoder sources.
   It verifies no matching request has already been admitted, the original
   registered template bytes, an absent consumption binding, no selected-state
   pending marker, and the exact previous selected identity and request hash.
   The runtime observation uses the original supplied READY and release pins.
5. Start the original fixed Mac sender asynchronously and the actual P4 Cancel
   Actor once. The Actor retains its original Send-window observation, NEG08
   zero-dispatch / HEPTA condition or NEG09 one-open / independent-foreground
   condition, selected/UI/viewport CAS, one Cancel and subsequent read-only
   drain. Its action logic is not reimplemented in the coordinator.
6. Join the sender with the Root capture's original deadline, wait, both EOF,
   joined capture worker and original-created output inode checks. The new
   finalizer publishes the exact original seven-field `RESULT.json` schema.
   Its separate output-capture sidecar remains an original descriptor.
7. Obtain the actual retained Actor result. Derive the only accepted scope,
   native request digest and provider run from the matching result and final
   original observation, never from a new task identifier supplied by this
   coordinator. Form the phone capture plan with the original READY model
   identity and binding, exact request/template/app-scope and final source pins.
8. Execute the fixed phone capture recipe once. Read back the actual wrapper,
   then recover the complete fixed archive in the existing 512 KiB transport
   unit. Each chunk checks full9 generation; complete reconstruction checks the
   original total length, SHA256 and single-gzip regular-only closed archive.
   Archive member source code is never executed.
9. Copy the sender and Actor's four original transport byte streams to the new
   P4 capture inputs. Each mapping preserves its original Mac descriptor and a
   separate P4 retained-copy descriptor. Build and run the original P4 collector
   once, preserve its actual terminal result and recover its complete archive.
10. Write the exact CPU closure plan to its fixed new Mac input namespace. Call
    `root_cpu_negative.py` once with either `--close-originals-once` or
    `--qualify-original-case-once`. Only the existing closer can validate the
    original CPU safe point, issue its physical receipt and grant that layer's
    pass. This entry grants no host-isolated or business qualification.

## Exact original phase contracts

Every host phase retains exactly these seven descriptors:
`intent`, `child`, `result`, `stdout`, `stderr`, `stdin`, `output_capture`.
`stdin` is null only when the original phase has no input. The successful
`RESULT.json` itself remains exactly seven fields, with no added sidecar key.

| Closure field | Actual phase | Original execution contract |
|---|---|---|
| `sender.execution` | `negative-sender` | Fixed sender runs on Mac; 660-second original host capture; no stdin |
| `actor_execution.host` | `negative-cancel-actor` | Fixed P4 Actor argv; `wait_seconds + 240` remote budget and original `+30` Root host envelope |
| `phone.execution` | `phone-negative-capture` | Original phone request recipe, 120-second phone limit and original `+55` Root host envelope |
| `p4.execution.host` | `negative-p4-capture` | Fixed P4 collector argv; 90-second remote budget and original `+30` Root host envelope |

The preflight, staging, raw-read and archive-chunk operations are separate
recorded phases. They do not replace any of these four original case phases.
The original native turn/model limits are not increased by host capture waits.

## Current execution block and required source cascade

`FINAL_AUTHORITY = None` is an intentional source-level admission block.
`templates/FINAL-AUTHORITY.template.json` is only a structural guide. Supplying
that data through a case plan cannot authorize execution.

Before a future execution, a separately reviewed source generation must bind:

- The actual adopted live policy and adoption evidence, including its current
  complete prior frontier. The old sides01 frontier and offline candidate hash
  are not a substitute for this evidence.
- The actual final runtime, consumer, readiness, combination, configuration,
  service and source-seal pins; the eight-member Cancel package; the current
  active/runtime template and current production source map.
- The full CPU verifier, phone collector, P4 collector, sender, Root transport
  and CPU closer source cascade, including all `FINAL_DEPENDENCIES`, fixed
  configuration/service identities and sibling source pins.
- Preserved source-generation derivation originals. The authority records them
  and the CPU assembler checks the executable dependencies; they are not a
  license to fill arbitrary values into unbound source literals.

The retained Root transport source must still reverse exactly through its seven
approved RHS slots to the full 71,820-byte `50a500e0…` template. The coordinator
loads that complete module with a non-main name and uses its existing transport
methods; it does not rewrite the Root body, call its old native-case `run()` or
pretend its old policy/lease main is current authority.

The active-runtime successor supplied by the implementation agent is retained
as a source fixture. Its four future release/policy slots remain unbound. The
tests use explicitly synthetic in-memory values only to exercise the actual
pure plan validators; those values are neither source authority nor installed
state.

## Failure and ownership behavior

Every external phase has an outer one-attempt ticket written before entering
the original transport. An interrupted call cannot become a successful empty
child set. A returned asynchronous sender remains owned by the original Root
capture maps until the original join and EOF checks complete.

Failure closes or stops only the capture resources owned by the original Root
transport. It does not signal an unknown remote process or claim remote cleanup
from closing a host pipe. The failure result keeps the same nonce, original
directories, all known output/capture records, unresolved call tickets and an
explicit false `remote_terminal_or_cleanup_proven`. It forbids same-identity
replay, a replacement identity and automatic continuation. Partially created
directories are retained.

The entry does not promise hard real-time filesystem/process-spawn completion.
It preserves the original transport's execution/EOF deadlines and honest
unknown-state handling. No invented aggregate phone memory or scan qualification
is attached to the local tests.
