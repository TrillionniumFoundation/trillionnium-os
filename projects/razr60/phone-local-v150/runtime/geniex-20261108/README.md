# GenieX single-request worker candidate

`worker.c` implements one process, one model instance, one chat-template application,
and at most one `geniex_llm_generate` or `geniex_vlm_generate` invocation. It uses the
unmodified GenieX v0.10.0 C ABI, pinned to commit
`071f609995470bdb0e0769ab964754adfaab7e47`.

This directory is a new, independently reviewable runtime candidate. It does not
activate Hepta, clear its emergency stop, replay any request, edit a production
ledger, or authorize a phone action. Its result file is diagnostic evidence from
inside a process. A separate supervising process must observe actual termination
and decide completion versus cancellation. No CPU safe-point claim is emitted.

## Build

Use the Android NDK's AArch64 compiler and the **same official v0.10.0 Android
package** that will be loaded on the phone. The example below assumes the working
directory is this directory. Replace the three explicit paths for the local build
environment; do not compile the host stub into this binary.

```sh
/absolute/path/to/aarch64-linux-android31-clang \
  -std=c11 -O2 -Wall -Wextra -Wpedantic -Werror \
  -isystem vendor worker.c \
  -L /absolute/path/to/geniex-bench-android-arm64-v0.10.0/lib \
  -lgeniex -o /absolute/path/to/new-build/hepta-geniex-once
```

Record the compiler/version, worker and header SHA-256, official package and
`libgeniex.so` SHA-256, command, and final ELF SHA-256 in the device build evidence.
The worker checks the SDK's reported version at runtime, but a version string is
not a substitute for pinning library bytes.

The untouched upstream header uses two empty-argument prototypes that trigger
Android Clang 19's strict-prototype warning under `-Wpedantic -Werror`. Include it
as a system header (`-isystem vendor`) while keeping strict diagnostics on the
worker; do not silently rewrite the pinned third-party ABI header.

The separate host check is:

```sh
python3 tests/test_worker.py
```

It compiles against the fixed header with `-std=c11 -Wall -Wextra -Wpedantic
-Werror -O2`, using `tests/stub_geniex.c`. Its 22 test methods include multiple
fault cases. They cover original UTF-8 bytes and SHA-256, SDK debug output,
explicit 8192 context and CPU vision arguments, QAIRT zero context/layer create
arguments, real host signals and subprocess wait status, lifecycle failures,
output truncation, stop reasons, and private-file/create-only constraints.
These checks establish the worker's host contract. They do not establish Android
driver behavior, NPU release, model accuracy, or a production cancellation proof.

## Invocation and private files

All options accept one argument. Unknown or repeated options are rejected. The
worker accepts no network URL, shell command, automatic fallback, or retry flag.

Required arguments:

| Argument | Accepted value |
| --- | --- |
| `--request-id` | Exactly 32 lowercase hexadecimal characters. A supervisor must create a fresh request identity and claim; the string alone does not establish uniqueness. |
| `--mode` | `llm` or `vlm`. |
| `--runtime` | `llama_cpp` or `qairt`. |
| `--compute` | `cpu`, `gpu`, `npu`, or `hybrid`; QAIRT requires `npu`. |
| `--model` | Canonical absolute existing model path; `llama_cpp` requires a regular GGUF file. For the selected QAIRT package pass the bundle's `genie_config.json` file, not the bare directory; the fixed C API derives its model directory from the parent path. |
| `--prompt-file` | Canonical absolute UTF-8 user-message file. |
| `--result-file` | New canonical-parent absolute destination for JSON metadata. |
| `--text-file` | Distinct new canonical-parent absolute destination for raw generated bytes. |

Optional arguments:

| Argument | Accepted value / default |
| --- | --- |
| `--mmproj` | Canonical regular file; required for `llama_cpp` VLM, forbidden for LLM and QAIRT. |
| `--tokenizer` | Canonical regular file, when the runtime/bundle requires a separate tokenizer. |
| `--image` | At most one current image; VLM only. |
| `--system-file` | One UTF-8 system-message file. |
| `--grammar-file` | UTF-8 grammar passed as `sampler_config.grammar_string`, not as an OpenAI response-format schema. Disabled in the selected QAIRT integration after the actual discriminator abort recorded in `VALIDATION.md`. |
| `--vit-device` | `CPU`, `HTP0`, `HTP1`, or `GPUOpenCL`; only `llama_cpp` VLM. Unset leaves the SDK's default. |
| `--ctx-size` | Integer 0–32768, default 0; QAIRT requires 0 at the C create API. |
| `--max-tokens` | Integer 1–1024, default 256. |
| `--threads` | Integer 1–8, default 4. |
| `--timeout-ms` | Integer 1–300000, default 120000; cooperative deadline, not a guaranteed hard kill. |
| `--log-level` | `error`, `warn`, `info`, `debug`, or `trace`; default `warn`. |

Prompt, system, grammar, and image files must be regular files owned by the worker
UID, mode `0600`, with one hard link. Each text file is nonempty, at most 65536
bytes, valid UTF-8, and contains no NUL. The image is nonempty and at most 8 MiB.
Symlink or noncanonical input paths are rejected. File descriptors remain open;
inode, size, ownership, permissions, link count, and timestamps are checked again
after inference. Model/bundle, projector, tokenizer, shared-library, environment,
and image-decode content pinning remains the supervisor's responsibility.

Each output parent must be a canonical directory owned by the worker UID with
mode `0700`. Final names must not exist. Before SDK initialization the worker
reserves mode-`0600` `<name>.<request-id>.pending` files with `O_EXCL`. It fsyncs and
publishes by create-only `linkat`, removes the pending link, and syncs the directory.
An existing result is never replaced. Incomplete pending files remain after an
error or hard kill and are not successful results. The raw-text file is published
before the metadata that names and hashes it. No metadata file means no complete
worker result, even if a raw-text or pending file exists.

Every SDK call occurs after stdout is redirected to stderr. Capture stderr to a
private log. Do not parse a plugin's terminal output as the JSON result. The
result and raw-output files are the only machine-readable worker products.

Example arguments for a **new isolated smoke-test request**, after the controller
has prepared owned/private paths and the correct Android runtime environment:

```sh
hepta-geniex-once \
  --request-id 0123456789abcdef0123456789abcdef \
  --mode vlm --runtime llama_cpp --compute npu \
  --model /absolute/private/models/agent.gguf \
  --mmproj /absolute/private/models/mmproj.gguf \
  --vit-device CPU --ctx-size 8192 --max-tokens 256 \
  --prompt-file /absolute/private/new-request/prompt.txt \
  --image /absolute/private/new-request/current.png \
  --result-file /absolute/private/new-request/result.json \
  --text-file /absolute/private/new-request/generated.bin
```

The example request ID is illustrative and must not be reused. This command does
not itself isolate networking or the process group. Those are controller duties.

For the observed SM8750 Android package, the working loader order places the
package's private libraries first, then `/system/lib64`, then `/vendor/lib64`.
Putting vendor before system caused a `libbinder_ndk` symbol conflict in the
device experiment. Preserve the per-invocation environment; do not edit global
linker configuration. The HTP `ADSP_LIBRARY_PATH` uses semicolon-separated entries.
Exact phone paths and actual results belong in the device validation evidence.

## What the result proves

Schema: `hepta.geniex-once.result.v1`.

The result retains the SDK source pin, actual reported version, runtime, requested
compute/vision devices, resolver's actual device and layer value, create context,
generation limit, sampler request, input and formatted-prompt hashes, SDK return
codes, raw `stop_reason`, profile timings/token counts, PID/group/session IDs,
observed signal/deadline, and raw-output file/hash/source.

Model creation explicitly requests the SDK's
`GENIEX_POWER_MODE_SUSTAINED_HIGH_PERFORMANCE` (enum value 6), recorded as
`power_mode_create` and `power_mode_name`. It does not rely on the SDK's zeroed
low-power default or an undocumented environment override.

`sdk_rc` values are the **actual returned integers**, including failure codes.
An API that was not called is `null`. This includes a create failure before
generation, a version mismatch before resolver, and a create-success/null-handle
case in which no destroy call was possible. Profile is `null` when generate was
not called. Nonfinite profile floating-point values are represented by JSON
`null`, not invalid JSON numbers.

`generation_complete=true` requires all of the following at the worker's result
fence:

1. Generate was called exactly once and returned SDK success.
2. The SDK returned `eos` or `stop_sequence` and supplied its full text.
3. The returned text is within the bound, is valid UTF-8, and no truncation,
   observed signal, deadline, callback limit, or recorded error occurred.
4. Checked input metadata is unchanged, and model destroy/deinitialization
   returned success.

`length`, `context_length`, `user`, missing or unknown stop reasons, and any
negative generate return are incomplete, even if the text looks like valid JSON
or the SDK reports `eos` alongside its error. Empty successful SDK output is
preserved as empty; it still cannot satisfy a downstream action-schema check.
The worker itself does not parse or authorize generated actions.

When the SDK supplies `full_text`, its bytes are copied without cleanup or
normalization into the raw output. At the 1 MiB bound, the retained prefix is
marked truncated and is never complete. When generation has emitted callback
text but fails without `full_text`, the received prefix is retained with
`raw_text_source="callback_prefix"` and `raw_text_truncated=true`; it is never a
complete result. A missing output produces an empty evidence file with
`raw_text_present=false`. The C ABI exposes NUL-terminated strings without a
separate byte length, so the worker cannot recover bytes following an embedded
NUL in a faulty SDK string.

Exit codes are 0 for complete generation, 64 for invalid arguments, 65 for invalid
input files, 70 for incomplete/failed SDK work, 73 for output conflicts or invalid
output parents, 74 for I/O/publication failure, 124 for an observed cooperative
deadline, and 128 + signal number for an observed cancellation signal. A crash or
hard kill is a separate kernel wait status. `worker_exit_status_planned` is only
the intended exit code written before exit.

The result always states:

```json
{
  "production_receipt": false,
  "native_action_authorized": false,
  "process_exit_observed": false
}
```

## Cancellation and future r9 integration

SIGTERM, SIGINT, and SIGHUP handlers only set `sig_atomic_t` state. The worker
checks it at API boundaries, in the token callback, after generate, after SDK
cleanup, and before publishing metadata. A signal after the last token or while
destroying the model wins over an otherwise successful SDK result. The callback
returns false once a signal, deadline, or output bound is observed.

The SDK has no generic immediate-abort C entry point here. Init, model loading,
prefill, driver work, or cleanup can remain blocked without reaching a callback.
A supervisor must own a hard deadline, send SIGTERM to the isolated worker,
escalate to SIGKILL after a bounded grace period when necessary, and actually
reap the child. Process exit alone is not evidence of successful generation.

A compatible backend-neutral broker should add a **new versioned proof type**
instead of fabricating the existing r9 CPU-safe-point or token-ledger receipts:

1. Before spawn, durably bind a new accepted owner turn and request bytes to a
   create-only request claim. Keep all original global UNKNOWN, emergency-stop,
   lockscreen, viewport, focus, native-action, and no-automatic-replay guards.
2. Launch exactly one worker in an isolated process group/network namespace,
   with pinned executable, library, model/bundle, environment, prompt and image
   inputs. Record PID plus kernel start identity; a recycled PID is insufficient.
3. Serialize cancellation and successful-result acceptance in the **supervisor's
   own durable event order**. A cancellation accepted before completion acceptance
   makes all output unusable, including output published just before the signal.
4. On termination, record real `waitpid`/pidfd-observed status, raw result/file
   hashes, input identity, and cancellation ordering. Retain diagnostics even when
   output is not admissible. Do not call an exit-0 partial response “completed.”
5. Emit a new proof such as `isolated_process_exit.v1`, explicitly distinguishing
   normal complete generation, cancellation, hard-kill timeout, SDK failure, and
   unresolved exit. An unreaped child or missing binding remains UNKNOWN and
   prohibits dispatch/replay.
6. Teach the provider/cleanup validator to accept that new proof only after real
   device tests demonstrate lifecycle and NPU resource release. Preserve the old
   receipt readers for old requests. The C ABI does not expose the production
   r9 raw token-ID ledger, so the old receipt cannot be recreated truthfully.

Required device gates include normal generation with real wait status, cancel
during loading/prefill/decode, last-token cancellation race, driver/SDK errors,
hard-kill escalation, no orphan child/slot, no output admitted after accepted
cancellation, and a fresh isolated request succeeding after cleanup. Also repeat
correctness under the actual no-network namespace and target context. Host stub
tests are not these gates. This directory implements the worker, not that broker.

## Context and vision limits

For GGUF, `--ctx-size 8192` is an explicit create request recorded in the result.
Successful execution and accuracy at that context require device testing; a
smaller benchmark is not an 8192-context validation. The `n_gpu_layers` ABI name
is used by the resolver for NPU offload as well; its value alone is not a hardware
utilization measurement.

For the selected QAIRT SM8750/v79 Qwen3-VL bundle, the compiled logical
context limit is 4096. Its C API must still receive `n_ctx=0` and
`n_gpu_layers=0`, because the bundle owns these settings. Do not carry the GGUF
8192 ordinary profile into QAIRT. A prospective explicit
`daily-qairt-4096-v1` profile can reserve 256 generation tokens and 256 safety
tokens, leaving at most 3584 **tokenizer-counted** prompt/media tokens. This needs
the bundle's actual tokenizer and image expansion verified before admission; a
UTF-8 byte limit or a profile-name change is insufficient. Keep only the current
screenshot and necessary tool results; the 53-app schema also consumes context.

Use `--mode vlm` even for a no-image text smoke on this visual QAIRT bundle,
and explicitly pass its `tokenizer.json`. Its fixed vision graph is 512x512
with 256 visual tokens. The no-grammar synthetic position and complete-JSON
decision cases have run on the phone; their scope and original failures are
recorded in `VALIDATION.md`.

The pinned C ABI exposes `vit_device_id` but no image-min/max-token fields. The
worker records `image_token_bounds_exposed_by_abi=false` and does not invent an
unsupported option. Compare CPU versus HTP vision, check the runtime's real image
tokenization, and validate screen grounding with known geometry at a sufficient
image resolution. Fluent text or an `eos` stop is not visual correctness and
cannot authorize a phone tap.
