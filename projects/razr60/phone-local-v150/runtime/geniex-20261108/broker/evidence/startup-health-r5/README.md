## Request and receipt boundaries

It has its own startup request kind, intent and receipt schemas. The ordinary `run` signature and owner binding remain intact. `ORDINARY-BRANCH-AST.json` records exact body equivalence to the layout-r4 baseline after removing only the explicitly startup-only branches and restoring the existing owner-binding call. The original CPU receipt path remains outside this change.

## Cancellation and handoff

During native supervision, SIGTERM/SIGINT set a sticky cancellation gate so the unchanged r6 path can terminate and join the worker. Before publishing successful health, the helper restores the original terminating signal handlers and then checks that sticky gate, stop state and deadline. Inherited ignored or custom handlers are rejected. A signal arriving after restoration terminates the interpreter normally; there is no swallowing handler left between health and daily's lifecycle setup.

`listen_authorized=true` means this model health check completed and the code may enter `serve`. Every result also states `listener_ready=false`. It is not a listener readiness proof. A later stop retains all entry/request evidence and never deletes the one-attempt guard.
