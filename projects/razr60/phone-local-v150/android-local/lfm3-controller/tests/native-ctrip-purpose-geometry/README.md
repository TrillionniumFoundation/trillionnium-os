# Ctrip form purpose constraints and lossless pixel evidence

This gate does not operate a phone, run a model, authorize a purchase, or qualify Android dispatch. It verifies the complete production classes and verbatim Service methods against explicitly described host IO.

## Qualification boundary

The original whole-form comparison is still the first path. Its original schema, literal form maps, complete semantic comparison and rejection conditions remain unchanged. A separate fallback covers the recorded three-page Ctrip header geometry only when the whole form and all ancestors are unchanged, every census member and topology match, and all permitted old/new motion stays inside the fixed header and away from every non-trip form field and both complete action-target bounds.

Only `inspect_departure_year` and `query_observed_form` may use this constraint. It preserves explicit one-way/economy/passenger/city/date facts. It grants no trip-tab, header, scroll, generic click, calendar, result, coordinate or fallback authority. It makes no claim about missing accessibility actions, drawing order, all pixels being unobscured, or simultaneous native nodes.

The certificate crosses the original AX receipt or pixel metadata, immutable Frame, Domain, Session and private ActionGuard. AX reconstruction recomputes the complete pair. Pixel transport is decoded before interpretation. The last Service check binds the certificate to the original full census, exact observation, purpose/path, window/profile/owner and original full NodeRef. Equal-tree actions still execute the complete final census, window checks, live ancestor chain and one-use claim. Existing observation and action deadlines are unchanged.

## Lossless transport

Pixel form comparison maps use a closed five-field `hepta.ctrip-form-pair-transport.v1` wrapper with zlib DEFLATE, canonical base64, original UTF-8 length and SHA-256. Both original comparison schemas are preserved. Decompression must finish exactly with no remaining compressed bytes and match the original length/hash; malformed UTF-8, wrong schema/codec, dictionary requests, truncation, no progress, noncanonical base64, trailing JSON and size violations refuse. The original decoded cap is 262144 bytes and the whole PhoneObservation capture cap remains 8192 bytes. AX receipts are not compressed.
