## Running

Use an unchanged pre-fix component as `--source` and the candidate overlay (or integrated component) as `--overlay`:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -B run_host.py \
  --source "$BASELINE_COMPONENT" --overlay "$CANDIDATE_COMPONENT" \
  --actual-before "$ORIGINAL_BEFORE_JSON" --actual-after "$ORIGINAL_AFTER_JSON" \
  --java-home "$JDK17" --json-jar "$JSON_20240303_JAR" --output "$NEW_OUTPUT"
```

The runner pins both original AX inputs and the JSON parser, compiles the full native provider/session and existing pure dependencies, and copies the entire production `OutcomeExplanation` nested class byte for byte into an otherwise empty Controller wrapper. It records every compile input and that extraction. The full Android Controller lifecycle is not executed.

Task, lease, owner binding, installed identity, clock, worker receipt, and cleanup values are explicit host fixtures. No model, phone, login, agreement acceptance, Android IPC, or business operation is performed. Production installed/version/profile gates remain unchanged.

The old implementation compiles, then fails exactly four semantic targets: before phase, after phase, prompt blocker, and typed terminal presentation. The candidate must pass all 14 cases. Other cases cover required-node deletion, package/resource/class/parent/geometry/state changes, duplicate and mixed flight records, incomplete windows, restricted grammar and postparse admission, existing home/login/form behavior, final evidence binding, and retained query history.
