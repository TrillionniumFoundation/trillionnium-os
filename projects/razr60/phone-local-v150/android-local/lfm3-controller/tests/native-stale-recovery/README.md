# Native stale-action recovery host regression

The gate executes the production Session and action lifetime machine, the complete
native snapshot comparator, and verbatim Service census/comparison/receipt methods.
Its Android graph, installed-package endpoint, model decisions, clock and journal
are explicit synthetic host fixtures. No phone data is included in these tests.
This gate does not establish a real model response, Android dispatch or business
completion. A fresh ordinary UI task on the final APK remains necessary.

Tests require durable no-effect and drained proof, invalidate old runs and frames,
bind recovery to the new target and frame, and preserve failure/partial decisions.
A recovery context grants no tool or read authority. The separate typed read gate
owns Service drain and the once-per-task new read.

Complete two-tree rejection diagnostics are private per-action records. The
262,144-byte bound applies to the compact diagnostic object, not the complete
pretty-printed step-action file. Diagnostics cannot replace a refusal or claim
complete trees after truncation. The actual Controller projection excludes them.

The required budget scenario generates twenty exactly maximum-size compact
census objects through the production helper. It writes real pretty-printed
action files, executes the actual Controller history/prompt projections, and
exercises the actual inline and compact-reference terminal writer. This scenario
measures the diagnostic's contribution; unrelated application text can vary.
Existing 8 MiB result and 64 KiB journal limits still reject excess data.
Its screen and owner text are explicitly synthetic. The output preserves this
scenario's independent 198 assertions alongside the recovery case table.

Run with a full JDK 17 and the repository's pinned JSON jar:

```sh
python3 tests/native-stale-recovery/run_host.py \
  --source "$PWD" --output /tmp/hepta-stale-recovery-host \
  --java-home "$JAVA_HOME" --json-jar /path/to/json-20240303.jar
```

Optional `--previous-source` requires the exact frozen R16 tree. It compiles the
original production first, then requires actual runtime assertion failures for
the missing fresh-domain context and absent complete diagnostics. The default
gate has no dependency on a historical source checkout.

Outputs retain raw process streams and exit codes, exact source/tool inputs before
and after, verbatim extraction hashes, generated file metadata, unique case names
and assertion counts. Private device replay stays outside the repository.
