# Ordinary GUI-Owl settings and per-task inference routing host gate

Runs the unchanged 66 original settings cases first, then strict Java 8 API compilation and the new visual-settings cases on real JDK 17.

The new cases execute complete production LocalModelSettings, RuntimeConfigTransaction, LocalModelEngine, RuntimeInferenceAdapter, EngineInferenceAdapter, and ModelFileVerifier. The actual ordinary owner button bodies, application idle checks and service controller factory are extracted verbatim from current source and pinned in the receipt. One service and one cached controller survive text -> visual -> text commits.

Explicit host boundaries are Android views, service/task journal states, read-only process inventory, kernel memory text IO, and positive weight qualification only in the UI transaction cases. The VLM host port reserves the real shared-engine task lease and supplies controlled task cleanup proofs; it cannot execute a native model. Independent cases invoke actual asset admission and hash code for negative budget, full pin size, symlink, owner, link-count and content checks. Existing canonical VLM lifecycle/native gates remain necessary. No rendering, Android Binder behavior, positive model/backend qualification, phone operations, network or native inference is claimed.

The original transaction files and original assertions remain unchanged. Their runner only adds the now-required production VlmPins.java compile dependency.

The new integration stage generates an Engine copy with only its class-level final modifier removed to allow the declared positive-asset admission override. Every field and method body is byte-identical to current production; the runner verifies the one-change roundtrip and records both hashes. The unchanged original stage compiles and executes the unmodified final production Engine first. Actual negative asset checks instantiate the generated base Engine without any override.

The visual and dependent Qwen stage generate a MemoryAvailability copy that replaces only the unique `/proc/meminfo` input endpoint with an explicit synthetic byte stream. The unchanged production parser, `admits`, `lowMemory`, profile thresholds, Engine code and original SHA-error expectations still execute. The generated whole class is reversed byte-for-byte to the pinned production class. Each read records the existing ActivityManager fixture values and exact ASCII text; nonnegative values round down to KiB, and an invalid fixture tuple produces invalid text. No host-kernel memory measurement or missing-IO fallback coverage is claimed for this port. The original settings stage still compiles and executes its unchanged production inputs first.
