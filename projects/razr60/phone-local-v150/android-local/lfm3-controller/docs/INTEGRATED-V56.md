## Scope and authority

This standalone Android subtree remains outside the active Cargo/G1 source
closure. It changes no owner-open module activation, protocol or machine
qualification authority. Relevant review concerns are D3 lifecycle/concurrency
and D5 source evidence; this document grants neither integration review nor
release authority. The existing local model and the original owner instruction
remain the task inputs. Native/model artifacts, sampler and runtime pins are
unchanged.

Business behavior retained includes natural official-page owner constraints,
city/date confirmation, one native query invocation, exact native calendar
hierarchy, public-product evidence, and task-derived background target selection
within the saved owner range. Helper versionCode 5 and protocol v3 remain
required. Existing same-signer/installed-APK identity checks remain mandatory.

## Ordering, resources and cancellation

The process-wide single observation worker, busy fence and per-request original
deadline survive service replacement. Cancellation retires publication authority;
it does not claim a blocked Binder call exited. New task admission and recovery
also retain the unreleased Web-session and background-display conjunctions.
Relative to business v54, this adds v55's one process-wide observation worker;
it never creates one per task or replacement service. Tree/token bounds stay
unchanged, and a pending worker remains an admission fence until actual exit.

Native tree paths and parent classes travel with the same bounded BFS nodes and
participate in the observation digest. The native flight-query hook remains
immediately before the exact ACTION_CLICK call. Scope, owner authorization,
background generation/display, query single-attempt and outcome evidence retain
their existing checks.

Invalid runtime configuration is caught before modelFile access can escape UI
refresh. New task/text inference is disabled; existing Stop, cleanup and eligible
interruption recovery remain available. Final installed-identity IO is followed
by a Stop check, while unknown cleanup remains blocked.

Action-side graph, node, identity and some dispatch calls remain synchronous.
This integration does not close that main-looper responsiveness gap.

## Completion and negative claims

Flight city/date/query source paths do not establish a verified same-record
flight result. Flight result_ready_for_completion_gate remains false.
Public-product completion has a source path requiring corresponding detail/price
evidence and accepted native model navigation. It is not an order/purchase path,
and neither this path nor its fixtures prove a completed real phone task.

Host fixtures, a source manifest or an Android compile do not prove installation,
NPU/GPU inference, the OEM background-display behavior, simultaneous main-screen
use, application business success, signing custody or public release.
No phone action, model change, signing-key read or installation is part of the
source integration and host qualification work.

## Validation and failure retention

Run the complete strict host gate with a full JDK supporting javac --release 8,
-Xlint:all and -Werror. Preserve its exact production inputs and every failed
attempt. The runtime-config fixture follows the new concise UI/diagnostic
placement while retaining error, Stop, cleanup, saved-range and backend checks.

Run the separate background-target and actual Web business entrypoints as well:
query invocation, evidence, public-product composition, native/calendar parsing,
natural-owner comparison against real v53 classes, and unstarted retirement.
Page fixtures and the real JSON jar must match their original complete hashes.
A missing original city/calendar fixture or old-class identity is an explicit
blocked gate, never a synthetic substitute or an implicit pass. Keep the
original query runner result separate from supplemental strict lint.

The complete SOURCE-MANIFEST is regenerated after source/test/document changes.
Historical v54/v55 receipts are retained unchanged and do not qualify v56.

## Build, canary and rollback

Build from the new exact source inputs and generate a fresh
assets/hepta-build-identity.json through the established build_identity helper.
Never copy an old generated identity or APK into the v56 evidence chain.
A build requires the pinned SDK/NDK/runtime closure; no pin or compiler gate may
be relaxed to obtain an artifact.

Before any separately authorized device canary, require host results, a current
Android compile/assembly identity, the compatible verified helper, idle original
task ownership and confirmed prior background/Web cleanup. Stop on unknown
cleanup, stale authority, wrong display or changed target identity. Installation
is outside this host-only integration.

Rollback code and retained task/journal state are separate. Preserve unresolved
evidence and reconcile existing sessions without automatic redispatch. An old
helper/controller pair cannot be assumed compatible with current v3 state;
do not clear owner preferences, journals or existing failure evidence to make a
rollback appear clean.
