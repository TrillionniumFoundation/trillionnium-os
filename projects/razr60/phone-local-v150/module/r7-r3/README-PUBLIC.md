# r7-r3 module review sources

The release uses a separate module, activation and history namespace. It retains the same thirteen production provider files, model, native runtime, executor, client, helper binaries and budgets. The policy change is the three-atom IPC delta documented separately.

The old r7-r2 service was retired before policy application. Four original groups were absent in two independent censuses with kernel ESRCH observations; the original supervisor exit was 143. The journal preserved two timed-out actions and two completed executor records with exit 68. Those remain failed business tasks; no old request or action was removed or replayed.

The original unresolved-action gate remains authoritative. The activation census covers thirty retired groups. Existing twenty-two provider/configuration/service files and forty-four payload bindings are verified; only one activation-census payload row moves to the new namespace.

These are review sources, not an installable package. The projection index records original and public SHA-256 values. Private host paths, boot/process identifiers, retained-claim/configuration digests and operation bindings are replaced by required placeholders. A numeric process placeholder of zero is deliberately not a deployable identity. Executed checks used the original frozen bytes.

## Preserved preparation history

Root rejected the first sealer during static review because two activation-path assumptions referred to old revisions. It was never executed. The corrected r2 sealer verifies the exact parent activation path, size and hash, moves one payload row and preserves the other forty-three rows.

The first installer generator ran and failed on an occurrence-count assertion before writing an installer. The corrected generator accounts for two occurrences of the archive digest: a validation and its recorded receipt. It does not add another validation or repeat installation.

The first readiness reader was rejected in static review before phone use: its output and module paths pointed to wrong attempts. The separate r2 reader changes exactly these two paths. The current deployment driver pins that reader. The original generator remains historical and requires the explicit r2 correction.

The driver creates and checks the private host output directory before remote phases. A bounded gzip/base64 stage writes the exact original installer exclusively as root mode 0600, verifies its full hash and invokes it once. The large original shell is not placed directly in nested command arguments. Its GNU preflight uses the existing /proc/1/root SELinux view, loads no policy and submits no task.

Readiness exports bounded startup originals and hashes all module files; it does not repeatedly export large historical evidence as base64. Source preparation, policy audit and startup do not establish health, business, cancellation, cold-boot or daily-use qualification. Those outcomes belong to their own checkpoint.
