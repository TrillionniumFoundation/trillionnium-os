# v149 固定验收集合

这里是待执行的规格，不是通过记录。集合包含 **4 个真实模型业务场景、1 个直接组件场景、14 个定向负向场景**；本集合执行次数为 0。完整模型场景当前标为 `BLOCKED_MODEL_USAGE_LIMIT`，其余为 `NOT_RUN_FIXED_SET`。原 v149 源码与 `MANIFEST.json` 未改动，本目录使用单独的 `QA-MANIFEST.json`。

## 手动运行顺序

1. Root 先核对实际部署的源码、APK、native、helper 字节和手机显示配置；记录本轮真实设置基线。当前观察到的 stay-on 值为 **2**，结束后恢复本轮记录值，不能沿用历史脚本写 0。真实模型恢复必须有新的有界观察；不切换账号或模型、不反复探测额度。
2. 从 `fixed-acceptance-set.json` 选择一个用例，生成全新 nonce、任务身份和随机输入。文件只包含生成规则，没有可直接重放的旧请求。请求原文只留在私有运行证据中，源包只收规格和脱敏结果。
3. 需要业务合约的用例，将 `contract_recipe` 中所有运行时占位符替换为新数据的真实值，再用 `register_task_contract.py` 登记精确请求、当前 session/profile 和 coverage。固定集合不是调度器，不会自动发送任务、生成手机操作或重试。
4. 一次只运行一个手机用例。保留原 CLI 事件、native frames、图片参数、公开 App 回执和业务 sidecar。出现未知效果、断连、超时或取消就停止该用例；不重复原 effect、清理 claim 或消费过的模板来获得成功。
5. 复制 `case-result-template.json` 为本次独立结果，逐项填实际观测和证据 SHA。未报告的数据填 `null` 并说明原因；缺 token/计费数据不等于 0 token 或免费。时延必须注明时钟来源，不直接相减未校准的手机/Mac 时间。

## 判定边界

视觉场景要求新 JPEG 实际进入新模型决策、一次选择、同一公开快照中的挑战码/成功回执匹配以及显式返回。Unicode 场景同时要求输入点验证、点击“确认并读回”之后的公开原文与四行回执、最后返回；换行不能被静默归一化为空格。计算器和只读设置需先资格化当前 App 的真实唯一资源 ID，无法取得唯一节点则记录未支持，不能降低验证条件。

负向场景的 PASS 表示正确拒绝、无重复作用且清理/持久化符合要求，**不代表业务成功**。直接组件测试、隔离 fake-CLI/native fixture 和真实模型手机任务分开记录。涉及断连、native 超时、取消的隔离测试通过后，仍需在单独授权的新物理 native 任务中核对对应生命周期；不能用 fixture 替代实机层资格。

这轮集合不计算“日用成功率”。旧探索运行不进入分母，blocked 不算 pass；只有本套预先固定的完整新运行才计入对应统计。资源与 token/成本字段用于后续比较，不预设未经用户定义的商业 SLA，也不把缺测值补成估算。
